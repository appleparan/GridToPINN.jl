# 체험형 화면 전면 재설계 — 설계

대상 독자: 이 설계를 승인하고 구현 결과를 검토할 의뢰자.
작성일: 2026-10-05. 범위: `web/`의 화면. 커널(`src/`)과 WASM 빌드(`wasm/`)는 바꾸지 않습니다.

## 요약

- 화면을 "검증 페이지"에서 "독자가 CFD를 만져 보는 사이트"로 다시 만듭니다. 홈은 카드 격자,
  단계 화면은 왼쪽 사이드바와 좌우 분할(코드·조작 | 그림·오차)입니다.
- 버튼을 누르지 않아도 계산됩니다. 슬라이더와 대안 선택이 바뀌면 바로 다시 계산하고,
  슬라이더는 `step*.json` 목록 파일에서 만듭니다.
- Tailwind CSS 4, shadcn-svelte, mode-watcher(다크모드), uPlot(선 그림)을 도입합니다.
- 수치 계산은 기존 WASM 호출만 씁니다. JS로 다시 짠 수치 코드는 없습니다.
- `/verify`는 기능과 테스트 식별자를 그대로 두고 색과 글꼴만 새 테마를 따릅니다.

## 독자는 단계 화면 하나에서 질문, 코드, 조작, 결과를 함께 본다

경로는 세 가지입니다.

| 경로 | 내용 | 사이드바 |
|---|---|---|
| `/` | 소개 한 문단, 9단계 카드 격자, 다크모드 버튼 | 없음 |
| `/step/1` ~ `/step/9` | 단계 체험 화면 | 있음 |
| `/verify` | 패리티 검증 (기존 기능 유지) | 없음 |

단계 화면의 배치는 다음과 같습니다. 폭이 좁으면(1024px 미만) 좌우 분할이 그림 위, 조작 아래의
세로 배치로 바뀌고 사이드바는 서랍으로 접힙니다.

```text
┌──────────────┬───────────────────────────────────┐
│ GridToPINN   │ 3단계 · 확산              ☾  검증 │
│              ├───────────────────────────────────┤
│ ✓ 1 미분과   │ 벽이 움직이면 물과 꿀 중 어느     │
│     Newton법 │ 쪽이 더 깊이 끌려오나?            │
│ ✓ 2 시간전진 ├─────────────────┬─────────────────┤
│ ● 3 확산     │ 적분기 [E|RK4|CN]│                 │
│ ○ 4 대류     │ ┌ code ───────┐ │   실시간 그림   │
│ ○ 5 Poisson  │ │ …           │ │                 │
│ …            │ └─────────────┘ │ 오차 3.2e-4 ✓   │
│ ○ 9 GPU      │ N  ──●──── 100  │ ▶ ⏸ ↺           │
│              │ ν  ────●── 1e-6 │                 │
│              ├─────────────────┴─────────────────┤
│ «접기        │ ← 2 시간 전진        4 대류 →     │
└──────────────┴───────────────────────────────────┘
```

- 사이드바는 9단계의 번호, 제목, 질문을 보여 줍니다. `index.json`에 없는 단계(현재 4~9)는
  흐리게 "준비 중"으로 표시하고, 들어가면 질문과 "준비 중" 안내만 나옵니다.
- 홈 카드는 번호, 제목, 질문, 상태(체험 가능 / 준비 중)를 담습니다.
- 9단계의 제목과 질문은 `web/src/lib/curriculum.ts`에 둡니다(AGENTS.md의 단계 표와 같은 내용).
  빌드된 단계는 목록 파일의 제목·질문과 일치하는지 단위 테스트가 확인합니다.

## 조작은 목록 파일에서 만들고, 바뀌면 바로 다시 계산한다

슬라이더의 이름, 단위, 기본값, 범위, 설명, 프리셋은 `step*.json`의 `parameters`에서 읽습니다.
대안 선택은 `alternatives`에서 읽습니다. 화면 쪽에서 정하는 것은 "이 단계에서 어떤 값을 어떤
순서로 보여 줄지"뿐입니다.

- **슬라이더**: 범위가 양수이고 최대/최소가 1000배 이상이면 로그 눈금, 아니면 선형 눈금입니다.
  슬라이더 옆에 값과 단위를 표시하고, 숫자를 직접 입력할 수도 있습니다. 설명(`doc`)은 툴팁입니다.
  `display`가 있으면 화면 단위(km/h)로 보여 주고 WASM에는 계산 단위(m/s)로 넘깁니다.
- **슬라이더 창**: 목록 파일의 범위가 슬라이더로 쓰기에 너무 넓거나 0을 포함해 로그 눈금이
  안 되는 값(예: `rtol` 0~0.1)은 단계 설정에서 더 좁은 창을 줄 수 있습니다. 창은 목록 파일
  범위 안에 있어야 하며 단위 테스트가 확인합니다.
- **프리셋**: `presets`가 있으면(3단계 ν의 물, 꿀) 슬라이더 아래에 칩으로 보여 줍니다.
- **대안**: 토글 그룹으로 고릅니다. 고르면 결과와 코드 패널이 함께 바뀝니다.
- **정밀도**: Float64 / Float32 토글을 모든 단계에 둡니다.
- **코드 패널**: 컴파일에 쓴 `.jl` 파일에서 목록 파일의 줄 범위를 읽어 보여 줍니다(기존
  `sources.ts` 재사용). 파일 이름과 줄 번호를 표시하고 Julia 문법 강조를 합니다.

다시 계산하는 방식은 계산 비용에 따라 둘로 나눕니다.

| 단계 | 방식 | 근거 |
|---|---|---|
| 1, 2 | 메인 스레드에서 동기 호출. 입력이 바뀌면 다음 화면 프레임에 다시 계산 | 호출 한 번이 짧음. 구현 중 실제 소요를 재서 16ms를 넘으면 Worker로 옮김 (현재 측정값 없음) |
| 3 | Worker에서 실행. 들어오면 자동 시작, 값이 바뀌면 200ms 뒤 처음부터 다시 시작. 재생, 일시정지, 처음부터 버튼 | 시간 전진이 길고 중간 결과를 계속 그려야 함. 기존 `client.run` 프레임 경로 재사용 |

나쁜 선택은 막지 않습니다. 발산하면 그림은 그대로 그리되 값이 `NaN`/`Infinity`가 되면
"발산" 배지를 띄웁니다.

## 단계마다 보여 주는 값과 그림은 다음과 같다

| 단계 | 슬라이더 | 대안 | 그림 | 숫자 표시 |
|---|---|---|---|---|
| 1 | P, Cd_closed, Cd_open, Froll, v0, h | 미분 방법 4가지 | Newton 반복별 오차 (로그 축). 고른 방법은 진하게, 나머지는 흐리게 | 닫힘·열림 최고속도, DRS 이득 (km/h), 반복 횟수, 해석해와의 오차 |
| 2 | P, m, Cd_closed, Cd_open, t_open, Δt, rtol | 적분기 3가지 | v(t). 최고속도 기준선, DRS 열림 시각 표시, 적응형은 걸음마다 점 | 끝 속도와 1단계 최고속도의 차, 걸음 수, 최소·최대 Δt |
| 3 | N, ν(물·꿀 프리셋), U, Δt | 적분기 3가지 | u(y) 수치해와 해석해, 프레임마다 갱신 | 시각 t, 최대 오차, 안정성 수 νΔt/Δy², 확산 깊이 |

안정성 수는 화면에서 슬라이더 값으로 계산하는 표시용 값입니다(곱셈 한 번). 해와 오차는 모두 WASM에서 옵니다.

## 화면은 작은 부품으로 나눈다

| 부품 | 위치 | 하는 일 |
|---|---|---|
| 테마 | `app.css`, 루트 `+layout.svelte` | Tailwind 4 토큰, 밝은·어두운 색, mode-watcher. 시스템 설정을 따르고 버튼으로 바꿈 |
| 껍데기 | `routes/step/+layout.svelte`, `lib/ui/shell/*` | 사이드바, 상단바, 이전·다음 링크 |
| 조작 | `lib/ui/controls/*` | `ParamSlider`, `AltPicker`, `PrecisionToggle`. 목록 파일 항목 하나를 받아 값 하나를 바인딩 |
| 눈금 | `lib/ui/controls/scale.ts` | 슬라이더 위치와 값 사이의 선형·로그 변환. 순수 함수 |
| 코드 | `lib/ui/CodePanel.svelte` | 소스 범위 표시와 문법 강조 |
| 그림 | `lib/ui/plot/LinePlot.svelte` | uPlot 래퍼. 테마 색, 크기 변화 대응, 마우스 위치 값 읽기 |
| 결과 | `lib/ui/Readout.svelte` | 숫자, 단위, 통과·발산 배지 |
| 실험 | `lib/experiments/step1.svelte` 등, `registry.ts` | 단계별로 조작과 그림을 조립하고 WASM을 호출 |
| 실행기 | `lib/experiments/runner.svelte.ts` | Worker 시뮬레이션의 시작, 일시정지, 다시 시작. 기존 `Diffusion.svelte`의 로직을 옮김 |

4단계 이후는 `lib/experiments/stepN.svelte` 하나와 `registry.ts` 한 줄을 더하면 붙습니다.
`$lib/gridtopinn`(연결 모듈)은 바꾸지 않습니다.

## 보이는 모습은 계기판처럼 차분하게 한다

- 중립색 바탕에 강조색 하나를 씁니다. 숫자는 고정폭 숫자 글꼴로 표시해 값이 바뀔 때 흔들리지 않게 합니다.
- 그림의 계열 색은 의미에 묶습니다(수치해, 해석해, 흐린 비교 계열). 밝은·어두운 테마 양쪽에서 구별되는 색으로 정합니다.
- 통과·발산은 색만으로 구분하지 않고 글자와 아이콘을 함께 씁니다.
- 슬라이더와 토글은 키보드로 조작할 수 있어야 합니다.

## 실패는 화면에 이유와 함께 보인다

- WASM을 불러오지 못하면(WasmGC 미지원 포함) 단계 화면에 원인과 브라우저 요구사항을 적은 안내를 띄웁니다.
- Worker 오류는 그림 위에 오류 문구로 표시하고 "처음부터" 버튼으로 다시 시작할 수 있게 합니다.
- 소스 범위를 찾지 못하면 코드 패널에 오류를 표시합니다(기존 동작 유지).

## 테스트는 기존 검증을 유지하고 조작 흐름을 추가한다

- 유지: 단위 테스트(`connector`, `handler`), `/verify`의 패리티·대안·그림·Worker 프레임 e2e.
- 고침: 홈 e2e는 카드 격자에 맞게 다시 씁니다.
- 추가 (단위): 선형·로그 눈금 변환, 슬라이더 창이 목록 파일 범위 안에 있는지, `curriculum.ts`와 목록 파일의 일치.
- 추가 (e2e): 슬라이더를 움직이면 결과 숫자가 바뀜, 대안을 바꾸면 코드와 결과가 바뀜,
  3단계가 클릭 없이 프레임을 그림, 발산 조건에서 "발산" 배지, 다크모드 전환, 기준 경로 `/sub`.
- 품질 관문: `bun run check`, `bun run test`, `bun run test:e2e`.

## 결정이 필요한 것과 가정

1. **통과 기준값 (결정 필요)**: 목록 파일에 통과 기준이 없습니다. 이번에는 단계 설정(`lib/experiments`)에
   기준값을 두고, 목록 파일로 옮기는 일은 다음 작업으로 미루는 것을 권합니다. 대안은 지금
   `wasm/entries`에 기준값을 선언해 목록 파일로 내보내는 것인데, WASM 빌드와 스키마, 호출 규약 문서를 함께 고쳐야 합니다.
   권장안의 기준: 1단계는 Froll = 0일 때 해석해와의 상대 오차 1e-8 이하(f32는 1e-4),
   2단계는 끝 속도와 최고속도의 상대 차 1e-3 이하, 3단계는 최대 오차가 U의 2% 이하. 이 숫자들은 제 제안값이며 근거 측정은 아직 없습니다.
2. **문법 강조 (확인 필요)**: shiki의 Julia 문법을 쓰려 합니다. 번들 크기와 사전 렌더링 동작은 구현 초기에 확인하고,
   크기가 크면 빌드 시점 강조로 바꿉니다.
3. **uPlot 크기 (확인 필요)**: 약 50 KB로 알고 있으나 확인하지 않았습니다.
4. **가정**: 설명글은 질문과 짧은 안내만 씁니다. 긴 교재 본문은 범위 밖입니다.
5. **가정**: AGENTS.md의 "화면은 의뢰자가 직접 만듭니다"는 이번 요청으로 바뀐 것으로 보고 그 문장과 `docs/architecture.md`의 웹 부분을 고칩니다.
