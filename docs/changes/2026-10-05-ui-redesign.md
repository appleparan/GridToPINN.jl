# 변경 기록: 단계별 체험 화면 (2026-10-05)

대상 독자: 화면을 이어서 만들거나 4단계 이후 체험을 붙일 사람.

## 1~3단계를 값을 바꾸며 체험하는 화면이 생겼고 계산은 모두 Julia 커널이 한다

- 화면이 검증 페이지 하나에서 "홈 카드, 단계별 체험 화면, 검증 페이지"로 바뀌었습니다.
  1~3단계는 슬라이더, 대안 선택, 정밀도 전환으로 값을 바꾸면 그림과 오차가 다시 계산됩니다. 4~9단계는 "준비 중"입니다.
- 계산은 전부 컴파일된 Julia 커널이 합니다. 화면에는 수치 코드를 쓰지 않았습니다. 커널 출력에 화면이 적용하는 산술은
  두 가지뿐입니다. 긴 곡선을 그릴 때 솎아 내는 것과, 재생 중인 그림의 머리 점 하나를 두 표본 사이에서 보간하는 것입니다.
  2단계의 "직전 계산 걸음의 속도"는 보간값이 아니라 적분기가 실제로 계산한 마지막 걸음의 값입니다.
- 통과 기준은 제안값이고 측정으로 정하지 않았습니다. 수렴 차수를 보여 주는 화면은 아직 없습니다.

## 단계마다 화면 하나, 조작은 목록 파일에서 만든다

단계 하나를 추가하는 비용을 컴포넌트 하나와 `registry.ts` 한 줄로 줄이기 위해서입니다. 슬라이더, 프리셋,
대안 선택, 코드 줄 범위는 `stepN.json`을 읽어 만듭니다. 구조는 [../architecture.md](../architecture.md)에 있습니다.

- 1, 2단계는 결과를 애니메이션으로 재생합니다. 전체 곡선은 흐리게 먼저 보이고 밝은 곡선이 시간에 맞춰
  드러납니다. 재생, 일시정지, 처음부터 버튼이 있고 모션 줄이기 설정이면 바로 끝까지 보입니다.
- 3단계는 Worker에서 한 프레임씩 돌려 애니메이션 프레임 하나에 한 프레임만 그립니다. 값이 바뀌면 이전
  실행의 프레임은 버립니다.
- 그림 위에 마우스를 올리면 그 위치의 x와 각 곡선의 y가 범례 아래에 나옵니다. 긴 곡선은 그리기 위해 픽셀당 약 4점으로
  솎아 내며 최소·최대는 남깁니다. 읽는 값과 `data-points`는 전체 배열 기준이고, 마우스 값은 그려진 표본입니다.
- 그림은 uPlot, 코드 강조는 shiki, 컴포넌트는 shadcn-svelte, 다크 모드는 mode-watcher입니다.
  글꼴은 Pretendard와 JetBrains Mono를 사이트에서 직접 내려 줍니다.
- 나쁜 선택은 막지 않고 "발산"이나 "기준 초과"로 보여 줍니다. 상태는 색만이 아니라 아이콘과 글자로도 표시합니다.

## 통과 기준은 제안값이고 몇 가지 한계가 남아 있다

- 두 칸 배치는 1280px(xl)부터, 사이드바는 768px 미만에서 서랍이 됩니다. 설계 문서는 둘 다 1024px로
  적었으나, 생성된 사이드바 컴포넌트의 기본값이 768px라 고치지 않았습니다.
- 통과 기준은 `web/src/lib/experiments/config.ts`의 `PASS`에 둡니다. 목록 파일에 넣으려면 `wasm/` 선언을
  늘려야 하는데, 값에 근거가 없는 지금은 그럴 이유가 없다고 판단했습니다. 이 값은 측정한 것이 아니라 제안입니다.
- `@lucide/svelte`는 `^1.48.0`으로 고정했습니다. 사용자의 bun 설정이 공개 7일 미만 패키지를 막기 때문입니다.
- shadcn-svelte 스타일은 CLI 기본값인 "vega"입니다. `init`을 비대화형으로 돌릴 수 없어 `components.json`과
  테마 CSS를 손으로 썼고 `shadcn-svelte/tailwind.css` 가져오기도 직접 넣었습니다. 의도한 중성 톤과 같은지는 확인하지 않았습니다.
- 수렴 차수 화면, 4~9단계 체험, 1280px 미만에서 두 칸 배치는 없습니다.
- 반론: 재생이 길면 결과를 늦게 보게 됩니다. 1단계는 최소 1.5초, 최대 6초이며 재시작 버튼이 있고,
  모션 줄이기 설정에서는 재생하지 않습니다.
- 1~3단계 컴포넌트는 조작, 코드, 경고 블록을 복사해 쓰고 있습니다. 4단계를 붙일 때 공통 컴포넌트로 뽑습니다.
- `data-muted-runs`와 `data-compute-ms`는 시험과 진단용 속성입니다. 화면 기능이 읽지 않습니다.
- 3단계 프레임 간격은 화면 갱신 주기에 묶여 있어 탭이 백그라운드면 멈춥니다. N이 400을 넘거나 Float32인 경우는 측정하지 않았습니다.

## 4단계를 붙이기 전에 공통 블록을 뽑아내야 한다

- 4단계를 붙일 때는 `StepN.svelte`를 만들고 `registry.ts`에 한 줄을 더합니다.
- `PASS` 값은 각 단계의 수렴 측정이 나오면 그 값으로 바꿉니다.
- 배포 전에 shiki 덩어리(1.17 MB)가 느린 회선에서 문제가 되는지 확인합니다.
