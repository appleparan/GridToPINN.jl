# 변경 기록: 1~3단계 아키텍처 재정리 (2026-10-05)

## 요약

- WASM 래퍼가 커널을 다시 구현하고 있어서 "화면의 코드가 곧 실행 코드"라는 약속이 깨져 있었습니다.
  래퍼를 없애고, 커널을 그대로 컴파일하는 얇은 진입점으로 바꿨습니다.
- 래퍼를 만든 근거("키워드 기본값, 함수 인자, 브로드캐스팅은 컴파일되지 않는다")는 WasmTarget 0.5.3에서
  사실이 아닙니다. 실험으로 확인했습니다.
- 저장소를 커널, WASM 빌드, 웹 세 층으로 나눴고, 목록 파일과 일치 검사를 선언에서 자동 생성합니다.
- 2단계의 가속 모델과 Dormand–Prince 계수에 오류가 있어 고쳤습니다. 이 부분은 동작이 바뀝니다.

## 무엇이 문제였나

1. `src/step{1,2,3}_wasm.jl`이 Newton 반복을 세 번, RK4, 확산 우변, Crank–Nicolson을 각각 Float64 전용으로
   다시 구현했습니다. 화면에 보이는 커널은 브라우저에서 실행되지 않았습니다.
2. 2단계가 1단계의 `newton`과 최고속도 계산을 복사했습니다. 단계별 하위 모듈이 같은 이름을 내보냈습니다.
3. 2단계 모델 `a = (P/(ρA))·(1 − (v/v_top)³)`은 차원이 가속도가 아니고 질량이 없습니다.
   DRS가 열리는 사건도 없어서 "열리는 순간 간격이 촘촘해진다"를 보여줄 수 없었습니다.
4. 적응형 적분기는 `t_end`가 없고, Float64 계수 때문에 Float32가 승격되며, 5차 해의 계수 두 개가
   틀렸습니다(`-275/512`, `512/1575`. 표준값은 `-2187/6784`, `11/84`).
5. 1단계 테스트가 `test/runtests.jl`에서 사라져 있었습니다. `Project.toml`의 `Test` UUID가 틀려서
   `Pkg.test()`가 실패했습니다.
6. Float32 내보내기가 없었습니다. 모든 단계가 `step1.wasm` 하나와 손으로 쓴 `step1_manifest.json`에
   들어 있었고, 기본값에 오류가 있었습니다(P = 50 W).
7. `web/`은 동작하지 않았습니다. e2e는 사이트를 열지 않고 `data:` URL로 `.wasm`만 불렀기 때문에
   빈 화면이어도 통과했습니다.

## 무엇을 확인했나

WasmTarget 0.5.3, Julia 1.12.7에서 작은 실험 모듈을 컴파일해 Node 26에서 실행했습니다.

| 구성 | 결과 |
|---|---|
| 제네릭 `newton(f, df, x0, tol, maxiter)`에 클로저를 넘겨 구체 타입 진입점에서 호출 | 컴파일됨, 네이티브와 같은 값 |
| 키워드 인자와 기본값 | 컴파일됨 |
| 브로드캐스팅으로 쓴 `rk4_step` (스칼라, Vector) | 컴파일됨 |
| `Dual{T}`로 자동미분 | 컴파일됨 |
| Float32 진입점 | 컴파일됨 |
| 가변 구조체 상태를 JS로 돌려주고 다시 넘기기 | 동작함 |

이전 보고서([step1_wasm_validation.md](step1_wasm_validation.md))의 "함수 인자 미지원"은 함수를 인자로 받는
함수를 진입점으로 직접 내보내려 했을 때의 오류였습니다. 구체 타입 진입점 안에서 부르면 문제가 없습니다.

## 무엇을 바꿨나

| 영역 | 이전 | 이후 |
|---|---|---|
| 커널 | `src/0N-*.jl`, 단계별 하위 모듈 | `src/stepN/*.jl`, 모듈 하나, 의존성 없음 |
| WASM 진입점 | `src/stepN_wasm.jl` (재구현) | `wasm/entries/stepN.jl` (타입 고정과 대안 선택만) |
| 빌드 | `scripts/build_wasm.jl`, 커널 패키지가 WasmTarget에 의존 | `wasm/` 별도 환경, `wasm/build.jl` |
| 산출물 | `step1.wasm` 하나 (커밋됨) | 단계별 `.wasm`, Float64와 Float32 (git에 넣지 않음) |
| 목록 파일 | 손으로 작성 | 선언에서 생성, 소스 줄 범위 포함 |
| 일치 검사 | 없음 | 같은 사례를 Julia, Node, 브라우저에서 실행 |
| 웹 | 동작하지 않는 껍데기 | 연결 모듈, Worker, 검증 페이지 |
| e2e | `data:` URL로 `.wasm`만 호출 | 빌드한 사이트를 Chrome으로 열어 검증 |

동작이 바뀐 곳은 2단계입니다. 모델은 `m·dv/dt = P/v − (½ρ·Cd·A·v² + F_구름)`이고, 닫힘 최고속도에서
출발해 `t_open`에 Cd가 바뀝니다. 수렴 값은 1단계의 열림 최고속도와 일치합니다.

## 근거

- 네이티브 테스트 505개 통과 (`julia +1.12 --project=. -e 'using Pkg; Pkg.test()'`).
- 측정한 수렴 차수: 전진차분 1.00, 중심차분 2.00, Euler 1.01, RK4 4.03, Dormand–Prince 한 걸음 6.05,
  확산 공간 2.0, Crank–Nicolson 시간 2.0.
- WASM 대 네이티브: 64개 사례, 비교 452건, 불일치 0건. 최대 상대 차이는 Float64와 Float32 모두 0.
- 브라우저 검증 결과와 배열 전달 측정값은 [../calling-convention.md](../calling-convention.md)에 있습니다.

## 가정과 확인하지 못한 것

- 차량 수치(600 kW, 800 kg, A 1.5 m², Cd 0.9/0.8)는 대표값으로 정한 가정입니다.
- WasmGC 브라우저의 최소 버전은 확인하지 않았습니다. Node 26과 개발 환경의 Chrome에서만 실행했습니다.
- 성능 측정은 WSL2에서 한 번씩 잰 값입니다.
- Float32에서 적응형 적분기의 `rtol = 1e-6`은 Float32 정밀도에 가깝습니다. 네이티브와 WASM 결과는
  같았지만 수렴 성질은 따로 조사하지 않았습니다.

## 다시 생기지 않게 하려면

- 진입점에 수치 코드를 넣지 않습니다. 커널이 컴파일되지 않으면 커널을 고칩니다.
- 빌드는 일치 검사 사례가 모든 내보내기와 모든 대안 선택지를 덮지 않으면 실패합니다.
- e2e는 콘솔 에러, 실패한 요청, 빈 그림이 있으면 실패합니다.
